# Автотесты Live-комнат PlatformaX

Актуальный Playwright-набор проверяет внешний вход гостя, закрытие и восстановление гостевого доступа, встречу с тремя участниками, двусторонний чат, отмену и подтверждение завершения, состав данных списка встреч

Тесты работают только на тестовом стенде, создают собственные комнаты с префиксом `QA-AT` (или локально заданным `QA_PREFIX`) и подтверждают после завершения начатых встреч `finished` / 0 участников. Собственный неопубликованный private/draft с 0 участников сохраняется для ретеста, его ID записывается в факты

## Запуск

```bash
npm run setup
cp .env.example .env
# В .env задать тестовый BASE_URL, OWNER_EMAIL и OWNER_STORAGE_STATE
# Для email/CSV: QA_STUDENT_EMAIL существующего тестового пользователя
npm test
```

Необязательные параметры: `OWNER_ID` для строгой проверки ID владельца и `QA_PREFIX` (например `QA-Codex-1026-AT`) для отдельных новых фикстур. Перед созданием комнат набор подтверждает пользователя через `/profile`, роль владельца через список Live, тестовый режим и отсутствие impersonation.

Пароли в режиме сохранённой owner-сессии не нужны. Файл состояния, .env, токены и подписанные ссылки в Git не попадают. Владелец должен быть авторизован на тестовом стенде, `Войти как` в этом наборе не используется

Для отдельного запуска с независимыми артефактами:

```bash
QA_OUT=qa-out/current npx playwright test tests/current-smoke.spec.js --output=test-results-current
npm run report
```

`npm run test:headed` открывает браузер. `npm run test:known` проверяет открытые проблемы отдельным набором, красный результат остаётся красным. `npm run test:all` запускает все файлы тестов, включая расширенные проверки и открытые проблемы

## Текущее покрытие

| Проверка | Что именно проверяется |
|---|---|
| H-2, внешний гость | Два независимых гостя проходят подписанное приглашение, получают HTTP200 с externalUrl без token/wsUrl и действительно открывают внешний URL кнопкой |
| Удаление и возврат гостя | Удалить гостя и закрыть вход через UI, замер естественного обновления лобби до новых join-запросов, серверный403, неактивный вход, Вернуть доступ через UI, прежнее приглашение снова пускает |
| Основной сценарий | Ведущий и два независимых гостя, счётчик3, сообщения в обе стороны, Отмена не завершает встречу, подтверждение завершает её без системного confirm |
| После завершения | Гость видит завершение в реальном времени; после F5 закрытый unlisted-доступ показывает понятный экран завершения либо отсутствия доступа, повторного входа нет |
| L-21 | Два свежих чтения списка: в строках встреч отсутствует creator.media |
| Email/CSV | Ручной email и CSV без заголовка находят известного QA-пользователя, draft сохраняет его персональное правило |
| Открытая L-22 | Отдельный строгий тест требует новую вкладку для внешней встречи, не подменяет это ожидание текущим поведением |

Датированные файлы `live-rooms.spec.js`, `regress-1012.spec.js` и другие имеющиеся наборы сохраняются как расширенные проверки. Текущие результаты запуска и сборка приведены в [RESULTS.md](RESULTS.md), а не выводятся из даты имени файла

## Границы

Основной smoke не заменяет полный регресс продуктов и тарифов, новые мобильные приложения, реальные Samsung/iPhone, аудио/видео и показ экрана. Готовые списки не проверены, чужие списки не меняются. Email/CSV-тест требует QA_STUDENT_EMAIL и пропускается с явной причиной, если параметр не задан. Нет свежего автоматизированного покрытия всех H-3, M-11, M-12, M-14, L-23, L-24. Внешний тест проверяет выдачу адреса и HTTP-навигацию, а не работу Zoom или другого сервиса

Неактивный вход после закрытия доступа проверяется вместе с серверным403. Отдельный замер естественного обновления до повторного join сохраняется в фактах и не заменяется утверждением об мгновенном UI-обновлении
