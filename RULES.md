# Правила для человека и любого ИИ-агента (Codex, ChatGPT, Claude, Cursor)

## Безопасность
1. Только тестовый стенд (`BASE_URL` в `.env`). Прод — никогда.
2. Пароли и ключи — только в `.env`, который не коммитится. Агент пароли не вводит и не печатает; токены (JWT) в логах не показывать.
3. Свои сущности — с префиксом `QA-AT`. Чужие комнаты не открывать, не завершать, не править. После прогона начатые свои комнаты завершены, сервер подтверждает `finished` и 0 участников (очистка в `finally`/`afterAll`). Свой незапущенный private/draft можно оставить для ретеста с `is_published=false` и 0 участников, записав ID и состояние; не стартовать его только ради очистки.
4. Нагрузку не давать: `workers: 1`, без циклов «сотни запросов».

## Как запускать и читать
- `npm test` запускает весь актуальный основной smoke. `npm run test:known` отдельно проверяет продуктовые ожидания открытых проблем и может быть красным. `npm run test:all` запускает все наборы. Один тест — `npx playwright test tests/current-smoke.spec.js -g "<код>"`.
- Красный тест — сначала открыть скрин/trace (`npm run report`), потом выводы.
- Плавающее (запись, M-4) — повторить 2–3 раза и писать «N из M», не «исправлено» по одному зелёному.
- Одна учётка = одна вкладка во встрече (вторая выбивает первую — так задумано).
- Панель встречи прячется без движения мыши — `wake(page)` перед кликом.

## Как добавить проверку
- В актуальном `tests/current-smoke.spec.js`: новая комната через существующий `helpers.createRoom()`, отдельные чистые гостевые контексты. Для прочих сценариев доступны `tests/live-rooms.spec.js` и его `newRoom()` / `live()`.
- В тексте ожидания писать код бага и человеческое описание: `expect(x, 'H-1: …')`.
- Состояние проверять по серверу (`h.state`, `h.inside`), а не только по экрану.

## Формат находки (для отчёта)
Где (URL) → шаги → факт (код ответа, данные сервера) → как должно быть → риск → скрин/trace → сборка `admin-XXXX.js` → роль/учётка.

## Актуальность и открытые проблемы

Текущий запуск и границы покрытия: [RESULTS.md](RESULTS.md). Проверка открытого бага сохраняет продуктовое ожидание и должна падать до исправления: не использовать `test.fail`, `skip` или обратное ожидание ради зелёного прогона. Сейчас отдельный набор `known-issues.spec.js` проверяет L-22 (новая вкладка для внешней встречи).

Не каждый открытый пункт покрыт автоматикой: телефонные приложения, поиск встречи в ЛК и полный адаптив перечислены как пробелы в README. Состояние прошлых запусков не подтверждает текущую сборку.

Одна сохранённая owner-сессия может быть общей серверной сессией: не запускать `Войти как` параллельно. Актуальный smoke использует владельца и независимых гостей, без impersonate.

Signed invite и JWT не печатать и не коммитить; `trace` и видео для новых сценариев выключены. Разные запуски получают отдельные `--output` и `QA_OUT`. Сначала дождаться завершения runner, затем править исполняемый тест.
